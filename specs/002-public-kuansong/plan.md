# 实施计划 · 宽松迁移

## 摘要
以现状基线为行为依据，在本项目建立独立公开工作树。先验证一个子游戏的完整接口，再迁移其余适配器与宿主。

## 技术上下文
延续现有 Node.js CommonJS。子游戏模块接收结构化观察并返回动作。宿主运行环境继续负责 OneBot、OCR 及持久化。private/ 和 cache/ 由 Git 排除。

## 宪章检查
既有行为以 001 为基线。游戏模块仅使用调用方传入的玩家可见观察，动作发送与恢复留在宿主。每个适配器须通过独立及集成验收。公开发布前核查源文件来源、许可和敏感数据。部署切换必须保留回退。

## 项目结构

- games/ 每个子游戏的模块及 CLI
- examples/ 合成输入
- docs/ 操作手册
- private/ 正式配置、密钥、地址、运行数据与私有迁移台账
- cache/lgtbot/ 外供上游快照，每份快照独立保存来源信息
- specs/ 当前与后续功能规范

## 交付顺序
先建立目录与验证契约，随后逐游戏迁移、宿主集成、发布审查和切换。出于发布要求，旧基线中的环境信息转入私有台账。迁移通过后才能清理旧路径。
