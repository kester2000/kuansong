# 功能规格 · 宽松源码迁移与公开发布

## 用户场景与验证

### US1 · 干净检出与安全发布（P1）
维护者从干净检出运行公开示例，配置正式环境时把敏感材料放进专用忽略目录。验收检查 Git 追踪列表、历史和发布产物，真实密钥、地址、配置、原始数据和外供缓存均不可出现。

### US2 · 独立接入子游戏（P1）
开发者可以分别调用每个子游戏，对合成输入验证建议、无动作和无效输入，无需 QQ 或其他子游戏。宿主使用同一接口执行集成验证。

### US3 · 平稳切换与持续迭代（P2）
操作者根据运行手册迁移旧源码与必要状态，验证新宿主，保留回退并获准退役旧路径。下一次更改通过 Spec Kit 追溯到需求、验收和发布证据。

### 边界
缺少私有配置时离线子游戏仍可运行。真实运行缺少必要配置须在连接前失败。重复事件和未知发送结果须沿用现状基线的恢复契约。外供上游快照须可追溯，无法确认分发权的内容留在缓存。

## 需求

- FR-001 宽松公开版独立保存代码与文档。生产秘密、服务器标识、私有业务数据集中在 private/，cache/ 专用于被忽略的缓存，包含 cache/lgtbot/。
- FR-002 每个已支持子游戏具有版本化开放接口和独立离线入口，使用可重放的玩家可见输入。对未支持的规则或输入返回可诊断结果。
- FR-003 保持现状基线的 QQ 命令、权限、游戏支持范围、发送和恢复行为。新增独立入口按游戏记录覆盖。
- FR-004 文档包含运行、部署、回退、迁移与 Spec Kit 迭代步骤。LGTBot 的可信上游指向官方 GitHub。
- FR-005 旧路径清理须由迁移、功能核验、备份恢复检查及明确路径确认先行。

## 成功标准

- SC-001 干净检出中，每款已迁移游戏可独立运行，所有合成契约验收通过。
- SC-002 拟公开提交、历史和发布产物中可确认的生产敏感信息与私有缓存为零。
- SC-003 新宿主通过现有回归及切换检查，退役前能按手册恢复备份。
