# 宽松项目宪章

## 核心原则

### I. 单一源码与游戏范围
宽松的源码、规格和验收归入 kuansong。服务器部署必须对应仓库的可识别提交。当前游戏范围仅限漫漫长夜，帮助与入局使用同一注册表。LGTBot 由上游独立维护，可信来源为其官方 GitHub。

### II. 框架掌握对局和通信
框架负责 SnowLuma 收发、身份和权限检查、会话归属、发送回执、归档和报告调度。游戏适配器负责规则、阶段、观察解析、动作合法性和游戏报告内容。只有框架可以把建议映射到 QQ 收件人并实际发送。

### III. 决策器可替换且遵守玩家视角
内置与外部决策器遵循同一版本化契约。请求仅包含当前玩家在决策时可见的私信与公开信息。决策器返回建议或等待，不获取传输凭据和真实路由标识。接口变更须用相同固定输入验证进程内和外部调用。

### IV. 行动可追溯，恢复防重发
发送前记录意图，发送后记录回执或待核对状态。重连、重启、重复事件或过期结果均不得造成额外发令。身份、规则或观测有歧义时暂停。档案必须能关联观察、建议、执行和结算。

### V. 完整循环验收后切换
上线前用固定输入验证从收件、决策、发送与恢复到结算和报告的完整循环。服务健康与功能验收分别记录。切换必须有可验证的备份和回退点，同一个 QQ 账号同一时间只由一个宿主控制。

## 私有数据与上游依赖

服务器配置、地址、密钥、私信、原图和生产数据集中放在 Git 忽略的 private/。外供上游快照放在 cache/lgtbot/ 并记录来源和版本。发布审核覆盖提交历史、构建产物和第三方授权。

## 规格与交付

当前功能、边界和验收由 specs/003-framework-decision 定义。切换步骤归 docs/operations.md。实现前更新受影响的规格、契约和任务，验收证据记录版本与材料。

## 治理

计划与发布须逐条核对宪章。修订记录理由及受影响规格。重定义或移除原则升主版本，新增原则升次版本，文字更正升修订版本。
