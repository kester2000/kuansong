# 宽松项目宪章

## 核心原则

### I. 先核对已有实现
需求必须关联源码仓库、入口、版本与验证证据。分别记录本地实现、历史部署和当前线上核验状态。新增功能前先检查宿主和适配器的职责及已有测试。

### II. 保持宿主与适配器契约
宿主管理 QQ 接入、可信身份、持久化和回执。适配器负责规则、观察解析和行动决策。帮助与入局校验使用同一支持清单。新增游戏必须记录人数、允许的规则变体和验收用例。

### III. 依据玩家可见信息行动
决策输入限于玩家本人当时收到的私信与当时公开的信息。复盘重建出的观测须标明来源。遇到身份、规则或图像歧义时暂停并保留可诊断证据。

### IV. 恢复时防止重复行动
在发送前记录意图，并保留发送结果与回执。重连补录须去重。发送结果不明确时先对账。配置、密钥、原图和私有对局数据留在运行环境，仓库保留脱敏索引与必要的哈希。

### V. 验证后认定完成
变更计划须列出受影响的端到端路径、回归、验证材料和回退方法。涉及现有运行逻辑的改动，按对应源码仓库的回归流程执行。线上结论须绑定实际验证时间和部署版本。

## 治理

每项变更按 spec、plan、tasks 跟踪。计划审查时逐条核对宪章。修改宪章须注明原因、版本和受影响规范。原则移除或重大重定义升主版本，新增原则升次版本，措辞更正升修订版本。
