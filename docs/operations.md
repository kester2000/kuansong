# 宽松运行手册

## 本地与部署边界

本地子游戏通过标准输入接收 JSON 并输出建议，详见 README。QQ 模式的目标链路为 OneBot v11 → 宽松宿主 → 子游戏 → 宿主校验及发送 → 回执。宿主管理可信裁判身份、入局、持久化、OCR 和补录。子游戏可用结构化输入单独运行。新宿主的启动命令将在完成迁移并通过验收后登记。

运行机器的配置统一放在 private/，目录权限仅授予运行账号和管理员。private/config/ 保存正式配置，private/ssh/ 保存密钥，private/deployment/ 保存服务器地址和内部部署记录，private/data/ 保存原始运行数据及固定回归夹具。公开示例一律使用合成数据。

cache/lgtbot/ 存放外部提供的上游源码快照。每份快照放入单独子目录，在该子目录记录来源、提供日期、版本或内容哈希、授权状态。缓存属于本地材料，不作为官方发布或公开构建的隐式依赖。

## 上线与退役

1. 建立旧目录及线上文件的脱敏库存。确认哪些属于宽松，哪些是共享服务。通过受保护渠道将私有配置和数据迁入 private/，留可恢复备份。
2. 逐游戏在合成或固定夹具下验证正常、拒绝和恢复路径。运行旧回归门禁，记录源码版本、材料哈希及结果。
3. 用干净检出运行本地离线验证。审查 Git 暂存内容、拟发布历史和构建产物中的秘密、私有数据与第三方授权。
4. 备份运行状态并保留回退入口。切换时保证同一个 QQ 账号只由一个宿主控制。核验健康、权限、加入、恢复和回执。
5. 确认新版本稳定且回退可用后，按用户确认的路径清理旧目录和服务器旧文件。保留其他服务及仍需归档的数据。

## 单一源码仓库

kuansong 是宽松唯一的源码仓库。服务器运行同一 Git 提交的工作树，私有配置和持久化数据在忽略目录内保存，上游工具仍按外部依赖管理。服务器运行中的修复先纳入 kuansong 的规格及提交再部署。迁移期间旧源码仅作为行为基线与回退入口，切换验收后按确认清单退役。
