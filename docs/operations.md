# 宽松部署切换与回退手册

[规格与接口](../specs/003-framework-decision/spec.md) 对应新候选源码。安装 Node.js 18 或以上，从根目录运行 `node framework/index.cjs`。正式配置默认读取 `private/config/bot.json`，游戏及宿主共同使用 `private/data/`。缺少配置时启动失败。自动回路由原有漫漫长夜策略驱动，外部进程通过私有配置中的 `decision.program` 和 `decision.args` 启用。

## 私有资料与部署基线

本地和服务器使用 kuansong 的同一 Git 提交。切换前登记新旧提交、运行账号、服务入口、共享依赖及回退目标。真实地址和部署日志存放在 private/deployment/，配置放在 private/config/，密钥放在 private/ssh/，会话、档案及回归材料放在 private/data/。按最小权限保护这些目录。外供 LGTBot 快照存放于 cache/lgtbot/，记录来源、日期、版本或哈希与授权。官方上游见 [LGTBot](https://github.com/Slontia/lgtbot)。

## 切换前验收

1. 核对旧环境文件归属，区分宽松源码、运行数据和共享服务。备份旧配置、会话、回执、档案和报告，在隔离环境验证恢复。
2. 在干净检出中审查源码、拟发布历史、构建产物和第三方授权。验证私有目录及缓存均被忽略。
3. 重放固定对局，验证群聊与私聊归属、漫漫长夜决策、动作校验、回执、断线补录、重启恢复、结算和报告。用同一契约测试内置策略和外部程序，执行现有完整回归。记录提交、夹具哈希及通过与失败项目。
4. 检查待发送和回执不明的动作。选择无进行中对局的窗口，或先验证可从一致的会话和回执状态恢复进行中的对局。

## 切换与验证

1. 停止旧宽松宿主写入和发令，保留 SnowLuma 等共享服务。对最新状态做一致性备份并记录回执边界。
2. 以目标 Git 提交启动新宿主，载入私有配置。先确认 QQ 连接、可信裁判、权限、对局状态与待核对动作，再进入获准的测试对局。
3. 完成从收件到报告的集成验收，核对无串局和重复动作。记录切换时间、线上提交和结果。只有验收通过才确认切换完成。

## 回退与退役

连接、发令、恢复或归档验收失败时，先停新宿主并保留其行动日志，核对切换后已发送和状态未知的动作，再以旧提交及一致状态恢复。验证旧宿主重新接入、能读取档案且无重复动作。新部署稳定且回退已验证后，按确认清单清理本地旧源码和服务器旧工作树，保留共享服务、私有档案及必要备份。
